# MINNEPLENKA

Production-ready editorial portfolio for Minneplenka, the architectural photography practice of Max Preobrazhensky.

The site is built with Next.js App Router, strict TypeScript, Tailwind CSS, React Hook Form, Zod, and Resend. It runs on Vercel and on OpenAI Sites through the included Vinext/Cloudflare build adapter.

## Local development

Requirements: Node.js 22.13 or newer and npm.

```bash
npm install
npm run dev
```

Open `http://127.0.0.1:5173`. Before deployment, run:

```bash
npm run typecheck
npm run lint
npm run build
```

## Environment

Copy `.env.example` to `.env.local` and replace every example value.

| Variable | Required | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Yes in production | Canonical origin used by metadata, JSON-LD, sitemap, and robots. No trailing slash. |
| `NEXT_PUBLIC_CONTACT_EMAIL` | Optional | Public studio email shown in the footer. If omitted, the footer links to the inquiry form. |
| `RESEND_API_KEY` | Yes for live inquiries | Server-only Resend API key. Never prefix it with `NEXT_PUBLIC_`. |
| `RESEND_FROM_EMAIL` | Yes for live inquiries | Sender on a domain verified in Resend. |
| `CONTACT_TO_EMAIL` | Yes for live inquiries | Private address that receives inquiries. |
| `UPSTASH_REDIS_REST_URL` | Recommended | Shared production rate-limit store for multi-instance deployments. |
| `UPSTASH_REDIS_REST_TOKEN` | Recommended | Server-only token for that store. |

Without the Resend values, the form returns an intentional `503` rather than discarding an inquiry. Without the Upstash values, a bounded in-memory rate limiter remains active; this is suitable for local development and a single warm instance, but a shared store is recommended for distributed production traffic.

## Contact delivery

1. Verify the sending domain in Resend.
2. Create a Resend API key and add it to the deployment environment as `RESEND_API_KEY`.
3. Set `RESEND_FROM_EMAIL` to a sender on the verified domain.
4. Set `CONTACT_TO_EMAIL` to the studio inbox.
5. Configure Upstash Redis REST credentials for consistent rate limiting across regions/instances.
6. Submit a real test inquiry after deployment and confirm both delivery and reply-to behavior.

The browser never receives the Resend key. The API route validates the payload again on the server, uses a honeypot and minimum-completion check, caps body size, anonymizes the client identifier, enforces rate limits, and sends plain-text email content.

## Content and portfolio images

Projects live in [`data/projects.ts`](./data/projects.ts); services and regional content are in `data/services.ts` and `data/locations.ts`. Image dimensions are centralized in `data/image-assets.ts`.

All initial portfolio entries and images are explicitly marked **Placeholder study**. Their project pages use `noindex, follow`-style safeguards and remain out of the XML sitemap. Before turning a record into a real commission:

1. Replace its images in `public/images/` and update intrinsic dimensions and accurate alt text.
2. Replace the sample title, place, date, description, captions, and keywords with verified project information.
3. Change `label` to `Commission`, set `isPlaceholder` to `false`, and remove `seo.noIndex`.
4. Rebuild and verify that the route is included in `/sitemap.xml`.

Do not reuse the generated placeholder imagery as evidence of completed client work. The generation notes are recorded in [`docs/PLACEHOLDER-IMAGERY.md`](./docs/PLACEHOLDER-IMAGERY.md).

## SEO architecture

- Canonical metadata, Open Graph, and Twitter cards use the Next.js Metadata API.
- Project, service, and regional pages generate unique metadata from typed records.
- `/sitemap.xml`, `/robots.txt`, and `/manifest.webmanifest` are generated by App Router metadata routes.
- JSON-LD covers `ProfessionalService`, `Person`, `Service`, `BreadcrumbList`, and `ImageObject` without inventing a street address, phone, awards, reviews, or prices.
- Filter combinations on `/work` are shareable query strings, while the canonical remains `/work`; each project keeps a normal server-rendered link and standalone route.
- Regional pages are limited to three useful, distinct guides rather than duplicated suburb pages.

### Google Search Console

1. Deploy to the final production domain and set `NEXT_PUBLIC_SITE_URL` to that exact HTTPS origin.
2. Add a Domain property (DNS verification) or URL-prefix property in Search Console.
3. Use the verification value Google provides; no token is included in this repository.
4. Submit `https://your-domain.example/sitemap.xml`.
5. Inspect the canonical homepage, service pages, regional pages, and each genuine project after they are published.

### Analytics

Choose the lightest platform that meets the studio’s needs. Vercel Web Analytics can be enabled in a Vercel project; GA4 can be added with `next/script` using the measurement ID issued for the production property. Do not invent an ID or load analytics before consent where applicable. After setup, verify page views, outbound email clicks, and successful inquiry events without sending form contents or other personal data to analytics.

## Deployment

### Vercel

1. Import this directory as the project root.
2. The tracked `vercel.json` selects the standard Next.js framework and runs `npm run build:vercel` (`next build`). Keep the Vercel build command enabled so the deployment produces the `.next` output Vercel expects.
3. Add the environment variables above to Production (and Preview if desired).
4. Deploy, run a test inquiry, and update the canonical URL if a custom domain is attached.

### OpenAI Sites

The normal `npm run build` command uses Vinext to build the Cloudflare worker. The tracked `.openai/hosting.json` contains the assigned Site project ID, and the Sites workflow packages `dist/` plus the hosting manifest. Do not replace the project ID when updating the same Site.

## Performance and accessibility notes

- The LCP hero is local, sized, and prioritized; below-the-fold images are lazy by default.
- Only the portfolio filters, image lightbox, and inquiry form hydrate on the client.
- Plus Jakarta Sans is self-hosted through `@fontsource-variable/plus-jakarta-sans`.
- Layouts reserve image dimensions to prevent cumulative layout shift.
- The mobile menu uses native disclosure semantics; the image viewer uses a native modal dialog and supports Escape and arrow keys.
- Motion is restrained and disabled through `prefers-reduced-motion`.
- A skip link, visible focus treatment, semantic landmarks, real links, labeled form controls, live form status, and descriptive alt text are included.

Lighthouse targets depend on the final hosting path, analytics, and replacement image weights. Re-run mobile Lighthouse after real photography and third-party scripts are added.
